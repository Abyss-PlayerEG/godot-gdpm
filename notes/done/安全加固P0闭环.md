## P0-1 关闭 TLS 证书校验 —— 下载/引擎链路已闭环

**问题**：全项目 8 处 httpx 请求使用 `verify=False`，中间人可篡改下载内容（插件/引擎二进制直接受影响）。

**结果（8 → 1）**：

- [x] 移除下载/引擎链路全部 `verify=False`（7 处）：`utils/download.py`、`commands/godot/install.py`、`commands/godot/common.py`、`commands/godot/list.py`；`download_file_chunked` 默认 `verify=True`
- [x] 未引入 `insecure = true` 配置项——链路清理后无自签名场景
- [ ] 剩余 1 处：`cli/app.py` 的 `api.github.com/contributors`（gdpm 自身元数据，非 Godot 下载链；本网络流量被重签，certifi 无法验证）→ 阻塞于网络信任方案（如 `truststore`），**保留在 todo**

**验收**：下载链 `grep verify=False` 为 0；全仓仅剩 1 处（已记录原因）。

## P0-2 修复失效的 SHA256 校验 —— 已按决策移除

**问题**：`get_asset_hash()` 请求的接口响应里没有 `assets` 字段，函数永远返回 `""`，"Hash verified" 分支从未生效（虚假安全感）。

**处置（2026-11-07）**：五项哈希来源探测全部阴性（302 头 / 查询参数 / 官网页面 / CDN 伴生文件 / 遗留镜像），唯一哈希源位于 GitHub 仓库而非下载接口同源提供，不满足"官方接口"标准。

- [x] 整体移除哈希校验（`get_asset_hash` / `get_release_asset` / `_match_release_file` / `sha512_file` 与 install 校验分支）
- [x] 移除后无"看似校验实则跳过"的路径
- [x] 下载文件名回归本地构造（官方 slug 规则保留，仅用于 URL 拼接）
- 后续若官方提供同源哈希（Node `SHASUMS256.txt` 模式）可重新接入

## P0-3 zip-slip 路径穿越 —— 已修复

**问题**：`extract_addon_from_zip()` 手动拼接 `dest / rel`，`rel` 直接来自 zip 成员名，`addons/../../evil.py` 可逃逸目标目录。

- [x] 新增 `_safe_member_path()`：拒绝绝对路径、`..` 成分与反斜杠变体（`..\..\`）
- [x] `Path(target).resolve()` 校验仍在 `dest.resolve()` 之下，越界抛 `ValueError` 丢弃
- [x] 单测覆盖三种攻击变体，断言目标目录外无文件

**验收**：`tests/test_utils_zip.py` 全过；`utils/zip.py` 覆盖率 99%。
