# 下载优化

> 状态：已实现（2026-11-19 核实）。并行下载 + 分片下载均已落地，SHA256 校验按 P0-2 决策移除。

## 目标

优化插件/引擎下载速度，支持并行下载和分片下载。

## 当前状态（已实现）

```
gdpm add:     单插件，分片并行下载（默认 4 片，上限 32）
gdpm sync:    多插件并行（并发 = parallel_downloads，默认 4），每个插件分片下载
gdpm godot install: 引擎安装包分片并行下载（片数取全局 parallel_downloads）
```

## 实现方案

### 并行下载（gdpm sync）✅

已实现于 `src/gdpm/cli/commands/sync.py`：

```python
parallel = clamp_workers(read_global_config().parallel_downloads)
semaphore = asyncio.Semaphore(parallel)
```

- 并发数由全局配置 `parallel_downloads` 控制（默认 4，收敛到 [1, 32]）
- 显示每个插件的独立进度条
- 单个失败不影响其他插件

### 分片下载（大文件）✅

已实现于 `src/gdpm/utils/download.py::download_file_chunked`：

1. HEAD 探测文件大小与 `Accept-Ranges`
2. 字节范围均分给 N 个线程（`clamp_workers`，默认 4，上限 32）
3. 各线程独立句柄按偏移直接写入目标文件——**无需合并步骤**
4. 预分配文件大小（`truncate`）避免碎片
5. 服务器不支持 Range / 文件过小时回退单流下载
6. 任一切片失败时清理半成品并回退单流
7. Ctrl+C 优雅取消（cancel 事件 + 半成品删除）

## 配置项

```toml
# ~/.gdpm/config.toml
parallel_downloads = 4     # 并行度（1-32，默认 4）: 同时下载的插件数 / 单文件分片数
```

> 原计划的 `chunked_threshold` / `chunk_count` 未实现：分片决策由服务器 Range 支持与文件大小自动判断，片数统一复用 `parallel_downloads`。
