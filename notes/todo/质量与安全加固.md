# 质量与安全加固

> 来源：2026-11 全项目代码评审。以下问题均已核实到具体文件与行号，非猜测。
> 优先级：P0 = 发布 0.1.0 前必修，P1 = 正式版前应修，P2 = 持续改进。

## P0-1 关闭 TLS 证书校验（安全）

**问题**：全项目 8 处 httpx 请求使用 `verify=False`，禁用了 TLS 证书验证，中间人可篡改下载内容（插件/引擎二进制直接受影响）。

| 文件 | 行 | 场景 |
|------|-----|------|
| `src/gdpm/utils/download.py` | 93 | 通用文件下载 |
| `src/gdpm/cli/godot/install.py` | 101 | 引擎安装包下载 |
| `src/gdpm/cli/godot/common.py` | 116, 158 | GitHub release 查询/下载 URL |
| `src/gdpm/cli/godot/list.py` | 147, 167, 184 | 远程版本列表 |
| `src/gdpm/cli/app.py` | 494 | 贡献者列表 |

**修复**：

- [ ] 移除全部 `verify=False`，默认校验证书
- [ ] 若曾因自签名/内网镜像需要关闭，改为配置项 `insecure = true` 显式开启并在输出中警告

**验收**：`grep -rn "verify=False" src/` 为 0 结果；断网/代理篡改场景下报清晰的证书错误。

## P0-2 修复失效的 SHA256 校验（安全）

**问题**：`get_asset_hash()`（`src/gdpm/cli/godot/common.py:155`）请求的是 `{GITHUB_API_URL}contributors`，即本仓库的贡献者列表 API——响应里根本没有 `assets` 字段，函数永远返回 `""`。`gdpm godot install` 的"Hash verified"分支因此从未生效，下载内容从未被校验。

**修复**：

- [ ] 改为从 release API 获取资产摘要：`GET /repos/{owner}/{repo}/releases`，在 `assets[]` 中按 `name` 匹配取 `digest` 字段（形如 `sha256:...`）
- [ ] 校验失败时中止安装并保留提示（现有失败清理逻辑已就绪）
- [ ] 增加单元测试：mock release 响应，断言命中/未命中/无 digest 三种情况

**验收**：人为篡改 zip 后安装必须失败；单测覆盖三种分支。

## P0-3 zip 解压路径穿越（zip-slip）

**问题**：`extract_addon_from_zip()`（`src/gdpm/utils/zip.py:157` 附近）手动拼接 `dest / dir_name / rel`，`rel` 直接来自 zip 成员名。恶意 zip 含成员 `addons/../../evil.py` 时，写入路径逃逸出目标目录。

注意：走 `extractall` 的路径（`extract_full_zip`）是安全的——CPython 会剥离 `..` 与绝对路径成分；风险仅在手动提取分支。

**修复**：

- [ ] 提取前对每个成员做 `Path(target).resolve()` 并断言仍在 `dest.resolve()` 之下，越界即报错丢弃
- [ ] 拒绝绝对路径与含 `..` 的成员名
- [ ] 单测：构造恶意 zip，断言不写出目标目录

**验收**：zip-slip 测试用例通过。

## P1-1 错误处理规范化

**问题**：全项目 25 处 `except Exception`，其中多处静默吞错（`except Exception: pass`），用户看到的报错（"找不到引擎"）与真实原因（GitHub API 限流）不符。

典型位置：

- `store/client.py` / `cli/godot/common.py` — 网络失败静默返回空
- `cli/sync.py:206`、`cli/add.py:110,128` — 单插件失败无原因输出
- `cache/index.py` — 索引损坏按空处理（合理，但应打 debug 日志）

**修复原则**：

- [ ] 网络类异常必须向用户输出根因（状态码/超时/DNS），至少一行 `[dim]原因[/dim]`
- [ ] 保留"降级继续"的行为，但降级时输出警告
- [ ] 区分"可预期失败"（404 → 提示版本不存在）与"意外异常"（打印异常类型）

**验收**：断网执行 `gdpm search xxx` 输出明确的网络错误而非 "not found"。

## P1-2 依赖解析器落地

**问题**：`src/gdpm/resolver/` 仍是占位模块。当前 `gdpm lock` 为线性遍历 + 惰性版本匹配，插件 A → 插件 B 的传递依赖无任何处理，依赖环未检测。

**修复**：

- [ ] 至少支持一层间接依赖：从 Store 获取依赖插件的 `plugin.json`/`project.json` 声明
- [ ] 依赖环检测与报错
- [ ] 版本冲突检测（同一插件被两方约束到不相交区间时报错并显示来源）
- [ ] `gdpm tree` 展示依赖树
