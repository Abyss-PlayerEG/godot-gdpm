# 质量与安全加固

> 来源：2026-11 全项目代码评审。以下问题均已核实到具体文件与行号，非猜测。
> 优先级：P0 = 发布 0.1.0 前必修，P1 = 正式版前应修，P2 = 持续改进。

## P0-1 关闭 TLS 证书校验（安全）

**问题**：全项目 8 处 httpx 请求使用 `verify=False`，禁用了 TLS 证书验证，中间人可篡改下载内容（插件/引擎二进制直接受影响）。

| 文件 | 行 | 场景 |
|------|-----|------|
| `src/gdpm/utils/download.py` | 93 | 通用文件下载 |
| `src/gdpm/cli/commands/godot/install.py` | 101 | 引擎安装包下载 |
| `src/gdpm/cli/commands/godot/common.py` | 116, 158 | GitHub release 查询/下载 URL |
| `src/gdpm/cli/commands/godot/list.py` | 147, 167, 184 | 远程版本列表 |
| `src/gdpm/cli/app.py` | 494 | 贡献者列表 |

**修复**：

- [ ] 移除全部 `verify=False`，默认校验证书
- [ ] 若曾因自签名/内网镜像需要关闭，改为配置项 `insecure = true` 显式开启并在输出中警告

**验收**：`grep -rn "verify=False" src/` 为 0 结果；断网/代理篡改场景下报清晰的证书错误。

## P0-2 修复失效的 SHA256 校验（安全）—— 已按决策移除校验

**问题**：`get_asset_hash()`（原 `src/gdpm/cli/commands/godot/common.py`）请求的是 `{GITHUB_API_URL}contributors`——响应里没有 `assets` 字段，函数永远返回 `""`，"Hash verified" 分支从未生效，下载内容从未被校验（虚假安全感）。

**处置过程（2026-11-07）**：

1. 曾修复为 godot-builds SHA512 对账（`get_release_asset`），实测 `gdpm godot install 4.7` 输出 `Hash verified ✓`，166MB 校验通过
2. 随后按"官方接口"标准调查哈希获取渠道，**五项探测全部阴性**：
   - 下载接口 302 响应头（仅 Cloudflare 跳转头，无 checksum/digest）
   - 下载接口查询参数（`checksum=` / `hash=` / `sha512=` / `verify=` 均无效）
   - 官网 archive/下载页内嵌哈希（0 处）
   - CDN 伴生校验文件（`.sha256` / `.sha512` / `.md5` → 403）
   - 遗留 tuxfamily 镜像（404 已关停）
3. **决策：整体移除哈希校验**——唯一哈希源 godot-builds 位于 GitHub 仓库而非下载接口同源提供，不满足"官方接口"标准

- [x] 移除死代码：`get_asset_hash` / `get_release_asset` / `_match_release_file` / `sha512_file` 与 install 校验分支
- [x] 移除后无虚假安全感：代码中不再存在"看似校验实则跳过"的路径
- [x] 下载文件名回归本地构造（`build_download_url` 官方 slug 规则保留，仅用于 URL 拼接）
- 后续若官方提供同源哈希（如 Node `SHASUMS256.txt` 模式）可重新接入

## P0-3 zip 解压路径穿越（zip-slip）

**问题**：`extract_addon_from_zip()`（`src/gdpm/utils/zip.py:157` 附近）手动拼接 `dest / dir_name / rel`，`rel` 直接来自 zip 成员名。恶意 zip 含成员 `addons/../../evil.py` 时，写入路径逃逸出目标目录。

注意：走 `extractall` 的路径（`extract_full_zip`）是安全的——CPython 会剥离 `..` 与绝对路径成分；风险仅在手动提取分支。

**修复**：

- [ ] 提取前对每个成员做 `Path(target).resolve()` 并断言仍在 `dest.resolve()` 之下，越界即报错丢弃
- [ ] 拒绝绝对路径与含 `..` 的成员名
- [ ] 单测：构造恶意 zip，断言不写出目标目录

**验收**：zip-slip 测试用例通过。

## P1-1 错误处理规范化

**问题**：全项目 25 处 `except Exception`，其中多处静默吞错（`except Exception: pass`），用户看到的报错（"找不到引擎"）与真实原因（GitHub API 限流）不符。

典型位置：

- `store/client.py` / `cli/commands/godot/common.py` — 网络失败静默返回空
- `cli/commands/sync.py:206`、`cli/commands/add.py:110,128` — 单插件失败无原因输出
- `cache/index.py` — 索引损坏按空处理（合理，但应打 debug 日志）

**修复原则**：

- [ ] 网络类异常必须向用户输出根因（状态码/超时/DNS），至少一行 `[dim]原因[/dim]`
- [ ] 保留"降级继续"的行为，但降级时输出警告
- [ ] 区分"可预期失败"（404 → 提示版本不存在）与"意外异常"（打印异常类型）

**验收**：断网执行 `gdpm search xxx` 输出明确的网络错误而非 "not found"。

## P1-2 依赖解析器落地

**问题**：`src/gdpm/resolver/` 仍是占位模块。当前 `gdpm lock` 为线性遍历 + 惰性版本匹配，插件 A → 插件 B 的传递依赖无任何处理，依赖环未检测。

**修复**：

- [ ] 至少支持一层间接依赖：从 Store 获取依赖插件的 `plugin.json`/`project.json` 声明
- [ ] 依赖环检测与报错
- [ ] 版本冲突检测（同一插件被两方约束到不相交区间时报错并显示来源）
- [ ] `gdpm tree` 展示依赖树
