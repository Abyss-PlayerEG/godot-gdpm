## 阶段一：find_engine_binary 兼容性修复

### 1.1 mono 版 .app 内二进制名硬编码

**问题**：`src/gdpm/cli/godot/common.py:239` 写死

```python
binary = app / "Contents" / "MacOS" / "Godot"
```

但 mono 包解压出的是 `Godot_mono.app`，内部二进制叫 **`Godot_mono`**。macOS 上查找 mono 托管引擎时 `.app` 分支落空，后续分支只匹配文件（`.app` 是目录）→ 整个函数返回 None。

**修复**：

- [ ] `.app` 内先试 `Godot`，不存在再试 `app.stem`（对齐 `utils/godot.py::detect_godot_binary` 已有的 stem 兜底逻辑）
- [ ] `open.py:80` 的 `.app` 特判同样处理（或直接删除——上游 `resolve_engine_path` 已解析到位，此处仅兜底历史钉子）

**验收**：tmp 目录模拟 `Godot_mono.app/Contents/MacOS/Godot_mono` 结构，`find_engine_binary` 返回该二进制路径。

### 1.2 确立唯一查找实现（确认项）

## 阶段二：创建命令修复

### 2.1 平台内联查找（P0）

**问题**：`create.py` 两处收编前的老代码，Windows/Linux 全中：

- `_set_project_engine()`（~336 行）：`glob("*.app")` + `not f.suffix` 兜底 → `.exe`（有后缀）与 `Godot_..._linux.x86_64`（`.x86_64` 被当后缀）都匹配不上 → "Skipping engine setup: engine not found"
- `_open_godot()`（~391 行）：同款死代码 → `--open` 时报 "no Godot engine configured"
- 两处均只查 `{tag}` 目录，**漏 `{tag}-csharp`**

**修复**：

- [ ] 两处内联查找整体替换为 `resolve_engine_path(name, version)`（common.py 已有，一次解决平台分支 + csharp 目录 + mono .app 三个问题）

**验收**：tmp 模拟三平台引擎目录布局，`_set_project_engine` 均能写入正确二进制路径。

### 2.2 --open 打开逻辑（P1，实验验证）

**问题**（实验 1 证实）：

1. `with subprocess.Popen(...)` 的 `__exit__` 会 `wait()` 子进程 → **命令挂起到编辑器关闭**（实测 sleep 2s 阻塞 2.0s），且 "Opening..." 在编辑器退出后才打印
2. `_open_godot` 查的是**全局默认引擎**，而不是用户交互中刚写入 `.engines-conf.json` 的引擎——可能打开完全不同的版本

**修复**：

- [ ] 启动改为 `open.py` 同款非阻塞写法：`Popen` + `wait(timeout=1)` 捕获启动失败
- [ ] 优先读 `target_dir/.engines-conf.json`（刚设置的钉子），无钉子再 `resolve_engine_path` 兜底；删除独立的全局默认内联查找

**验收**：`gdpm create --open` 启动编辑器后立即返回；打开的引擎与 `.engines-conf.json` 记录一致。

### 2.3 版本处理三个逻辑 bug（P1，实验验证）

| # | 位置 | 问题 | 实验证据 |
|---|------|------|---------|
| a | `create.py:143` 手写 `replace("-rc")` | `"4.7-rc1"` → **`"4.71"`**、`"4.7-beta2"` → `"4.72"`，生成不存在的 `features="4.71"` 与 `>=4.71.0` | 实验 3 |
| b | `create.py:64-86` 排序键 | `is_stable=0` + `reverse=True` 把 stable 优先也反转 → **预发布版排最前**，`versions[0]` 默认选中 beta | 实验 2：`['4.8-beta1', '4.7-stable', ...]` |
| c | `create.py:283` 子串匹配 | `"4.7" in "4.7.1-stable"` 为 True → 选择列表混入错误版本 | 实验 4：命中 `4.7`/`4.7.1`/`4.70` |

**修复**：

- [ ] a：版本标签生成改用 `normalize_version` + 规范化解析，废除手写 replace 链
- [ ] b：排序键改为 stable 优先（如 `(0 if "stable" in ver else 1, ver)` 配正序分组，或两段排序），保持版本降序
- [ ] c：匹配前双方规范化（去 `-stable` 等后缀、取主次版本）后精确比较

**验收**：单测覆盖 rc/beta/stable 排序与匹配三组用例（顺带启动 [质量与安全加固](质量与安全加固.md) P0-4 的首批测试）。
