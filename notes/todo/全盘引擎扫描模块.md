# 全盘引擎扫描模块（Rust）

> 来源：2026-11-07 设计讨论定稿。**状态：已入计划，待评审后实施。**
> 目标：`gdpm_rust_module` 的第一个真实工具模块——判断当前系统，扫描磁盘发现已安装的 Godot 引擎，供 `gdpm godot add`/解析链消费。

## 一、背景与动机

- 现状：引擎发现**完全手动**——`gdpm godot add <path>` 逐个注册（本 session 中 Steam 版 Godot 就是手动发现并注册的）
- 需求来源：引擎解析链计划（见 [引擎查找与创建命令修复](引擎查找与创建命令修复.md) 的"不在本期范围"）中提到的 Steam/系统引擎发现
- 载体：`src/gdpm_rust_module`（骨架已就绪，见 README）——扫描是 I/O 密集 + 可并行的场景，作为 Rust 模块的首个实战目标

## 二、设计决策（已定案）

| 决策点 | 结论 |
|--------|------|
| 系统判断 | Rust 编译期常量（`std::env::consts`）——wheel 按平台编译，编译时 = 运行时，比 Python 的 `platform.system()` 还简单 |
| 扫描档位 | **两档**：`quick`（默认，已知位置种子根）+ `full`（显式开启，盘根递归 + 三重护栏） |
| 安全边界 | **默认不执行任何扫到的文件**（`confirm=False`）；`--version` 确认只留给用户显式发起的 `gdpm godot add` 流程 |
| Rust/Python 边界 | **Rust 只负责"找到候选"**；版本确认/识别复用 Python 现有 `get_godot_version`/`detect_godot_binary`——不造第二套（create.py 双实现的教训） |
| 挂载点 | **硬性不跨挂载点、不跟随符号链接**（防循环 + 防网络盘挂起） |

## 三、API 设计

```python
gdpm_rust_module.scan_engines(
    roots: list[str] | None = None,   # 自定义根, None = 平台默认种子根
    mode: str = "quick",              # "quick" | "full"
    timeout: float = 30.0,            # full 模式时间预算 (秒)
    max_depth: int = 12,              # full 模式递归深度上限
    confirm: bool = False,            # 是否执行 --version 最终确认 (默认否)
) -> list[dict]
```

返回（去重后按版本降序）：

```python
[{ "path": ".../Godot.app/Contents/MacOS/Godot",
   "version": "4.7.2-stable",       # 解析失败为 None
   "source": "steam",                # steam | official | manual (按命中的根推断)
   "size": 167116800,
   "method": "filename" },           # filename | plist | exec
  ...
  # mode=full 时附带:
  {"errors": [{"root": "/Volumes/x", "reason": "permission denied"}]}  # 如实上报, 不静默
```

### 各平台已知种子根（quick 模式）

| 平台 | 候选根 |
|------|--------|
| macOS | `/Applications`、`~/Applications`、`/usr/local/bin`、Steam `~/Library/Application Support/Steam/steamapps/common/` |
| Windows | `C:\Program Files\Godot*`、`Program Files (x86)\Steam\steamapps\common\`、`%LOCALAPPDATA%\Programs`、PATH 目录 |
| Linux | `~/.local/bin`、`/usr/local/bin`、`/opt`、`~/.steam/steam/steamapps/common/`、flatpak/snap exports 目录 |

### full 模式三重护栏

```
剪枝:
  ├─ 系统目录黑名单: macOS /System /Library/Apple* /private /Volumes/com.apple.TimeMachine*
  │                  Linux /proc /sys /dev /snap    Windows C:\Windows C:\ProgramData
  ├─ 不跨挂载点 + 不跟随符号链接 (硬性规则)
  ├─ max_depth + 候选数上限 + timeout (AtomicBool 轮询可取消)
  └─ 名字预筛: 大小写不敏感 godot* (目录/文件均为入口)
容错: EACCES/断链 → 记入 errors 继续, 绝不炸整个扫描
```

### 候选识别三层漏斗（成本递增）

```
① 名字预筛    godot* / Godot*.app                          成本≈0 (遍历顺手)
② 便宜验证    魔数 ELF/Mach-O/PE + 大小 sanity (20MB~500MB)
              + .app 结构 + flatpak/snap wrapper (shebang)  成本≈1 stat + 4 字节
③ 版本提取    文件名正则 Godot_v?(\d+\.\d+...)-(stable|rc|beta|dev)
              macOS .app → 读 Contents/Info.plist           成本≈文本解析, 零执行
④ (可选)      confirm=True 才执行 `<bin> --version`         默认关闭, 见痛点 P0-1
```

## 四、内部架构

```
src/gdpm_rust_module/src/
├── lib.rs          # #[pymodule]: scan_engines 注册
├── platform.rs     # 系统判断 + 种子根 + 黑名单
├── scanner.rs      # 并行遍历 (每顶层根一个 worker), 剪枝/预算/取消/容错
├── detect.rs       # 三层漏斗 + 版本解析 + canonicalize 去重
└── progress.rs     # 可选进度回调 (Python::with_gil 节流上报)
```

## 五、痛点与对策（评审重点）

### 🔴 P0

**1. `--version` 确认 = 执行未知文件**
- 痛点：只有执行才能 100% 确认候选是 Godot，但扫描来的文件可能是恶意改名——扫描从"只读"变成"用户身份执行未知代码"
- 对策：**默认 `confirm=False`**，三层漏斗的①②③不执行任何东西；执行确认只出现在用户显式发起的 `gdpm godot add`（有预期的场景）

**2. "全盘"的权限与环境代价**
- 痛点：macOS TCC 弹窗（`/Volumes`、`~/Library`）、Time Machine 快照目录是扫描黑洞、Windows UAC、Linux 跨用户无权限、**网络挂载（NAS/SMB）可无限慢或挂起**
- 对策：不跨挂载点硬性执行；full 结果必须声明"可见范围内"；`errors` 字段如实上报被拒的根；时间预算硬上限

### 🟠 P1

**3. 识别准确性没有银弹**
- 痛点：文件名 `godot*` 撞上项目备份/编译输出/教程目录；魔数只证明"是可执行文件"不证明"是 Godot"；大小阈值可能漏掉 Godot 3 headless（~10MB）
- 对策：结果带 `method` 置信度分级；假阳交由用户在注册流程淘汰；阈值下限放宽 + 魔数必过

**4. 版本提取长尾**
- 痛点：自编译产物无版本号（`godot.linuxbsd.editor.x86_64`）；Steam 版版本串特殊（`4.7.2.stable.steam.ed1daf0bf`，本 session 亲历）；`.app` 内二进制无版本名
- 对策：文件名正则为主，`.app` 读 Info.plist 兜底，解析失败 `version=None` 交 Python 侧 `get_godot_version` 补

**5. 平台碎片化 = 规则长尾**
- 痛点：Linux deb/rpm/AppImage/flatpak/snap/自编译各一套；**flatpak/snap 的 exports 是 wrapper 脚本，魔数验证必失败**
- 对策：wrapper 单独识别分支（shebang + `org.godotengine.Godot` 特征）；规则表驱动（platform.rs 数据化），新形态加表不改逻辑

### 🟡 P2

**6. Rust/Python 双实现风险**
- 痛点：`utils/godot.py` 已有识别/版本函数，Rust 再写一遍 = create.py 内联查找双实现的重演
- 对策：边界写死——Rust 返回候选，确认与注册复用 Python 现有函数（本设计已定案）

**7. 进度/取消的 FFI 开销**
- 痛点：进度回调需 `Python::with_gil` + 节流；不做则 full 模式是"黑盒卡 30 秒"
- 对策：progress.rs 节流上报（与 4 片下载的锁同构）；`AtomicBool` 轮询取消

**8. 结果时效性**
- 痛点：扫到 ≠ 可用，引擎卸载/移动后列表过期；每次启动全扫浪费
- 对策：持久化结果 + 按根目录 mtime 增量失效（Phase 3）

**9. wheel 分发成本**（既有评估）
- 痛点：Rust 模块 → CI wheel 矩阵 +1（布局 A 的已知代价）
- 对策：接受（骨架 README 已记录），CI job 等原型验证有价值后再加

## 六、实施阶段

### Phase 1: quick 模式（先做）

- [ ] `platform.rs`：系统判断 + 三平台种子根表 + 黑名单表
- [ ] `scanner.rs`：种子根递归（深度/候选上限）+ EACCES 容错
- [ ] `detect.rs`：名字预筛 → 魔数/大小/结构 → 文件名版本正则 + plist 兜底 → canonicalize 去重
- [ ] `lib.rs` 注册 `scan_engines`，Python 侧冒烟（真实机器扫出已装引擎）
- [ ] 测试：tmp 目录模拟三平台布局 + 假阳样本（改名的非 Godot 可执行文件被魔数拦下）
- [ ] 与 Python 边界验证：Rust 候选 → Python `get_godot_version` 补全确认

### Phase 2: full 模式

- [ ] 盘根递归 + 三重护栏（黑名单/不跨挂载/不跟符号链接）
- [ ] timeout 预算 + `AtomicBool` 取消 + `errors` 字段
- [ ] flatpak/snap wrapper 识别分支
- [ ] 进度回调（节流）
- [ ] 测试：模拟权限拒绝根、超时中断、去重（同一引擎多根命中）

### Phase 3: 注册接入与缓存

- [ ] `gdpm godot detect` 命令封装（列表 + 一键 `godot add`）
- [ ] 结果持久化 + 根目录 mtime 增量失效
- [ ] 与引擎解析链计划对接（发现的引擎进入解析候选集）

## 七、验收

- [ ] quick 模式在真实机器 <1s 扫出全部已装引擎（含 Steam 版）
- [ ] 假阳测试：改名的 curl/随机二进制不进结果（魔数+大小拦截）
- [ ] 扫描全程零执行（`confirm=False` 路径无任何子进程 spawn，可用测试断言）
- [ ] full 模式超时能中断并返回部分结果 + errors
- [ ] `python3 scripts/check.py` 全绿
- [ ] 不与 `utils/godot.py` 产生重复实现（识别逻辑唯一）
